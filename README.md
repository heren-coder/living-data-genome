# The Living Data Genome — reproducibility package

Ledger-governed evidence lifecycles for accountable AI under limited observability.
Every quantity the paper measures is written by code in this package and nothing is
transcribed by hand. Ten of the thirteen tables are regenerated by `make_tables.py`
from the computed CSVs; running it and diffing its output against `data/tables/`
is the check.

The remaining three, together with the abbreviations list, are not measurements and
are not generated. Table 1 lists the constants the protocol declares before any
quantity can be read, Table 2 fixes the layer assignment, and Table 3 the placement
contract for the lifecycle vocabulary. These are stated by the author, and a
generator for them would be a generator for an authorial decision. The separation is
the same one the paper draws throughout: what is declared is declared, what is
measured is measured, and the two are never presented in the same voice.

Figures are generated on the same terms: `fig*.py` write into `scripts/`, and
`run_all.sh` moves them to `figures/` at the end of the run. Figure 1 is the one
exception and has no script: it is drawn by the author, and the file under
`figures/` is that drawing. Figure 15 draws on two sources, the misrouting
saturation of Section 3.8.1 and the seed convergence of Section 3.12, and it is
written at the size at which it is embedded, so that the script output, the file
under `figures/` and the image in the paper are the same object.

## Contents

| Directory | Contents |
|---|---|
| `scripts/` | 51 Python files and `run_all.sh`: 34 pipeline and measurement scripts, 17 figure scripts. Every script writes into `data/` and reads from it, so a run and its verification act on the same files |
| `data/` | 54 CSV files, all but one written by those scripts |
| `data/tables/` | 14 CSV files: one per table of the manuscript, plus the abbreviations list |
| `figures/` | 18 PNG files at 600 dpi. Figures 15 and 16 are byte-identical to the images embedded in the manuscript; the remaining sixteen are the untrimmed exports of the same plots, and differ from the embedded versions only in the white margin cropped when they were placed |

The package holds 143 files in total, excluding any `__pycache__` left behind by
a previous run. Every file under `data/` is written by the pipeline except
`shapley_geometry.csv`, which holds the product-form region geometry behind
Corollary C2 and is supplied.

## Running

    pip install -r requirements.txt
    cd scripts
    bash run_all.sh

`run_all.sh` is the entry point and needs nothing before it. It resolves paths
from its own location, so the package can be unpacked anywhere, and it runs the
whole sequence in dependency order: generation, the reliability protocol, the
governance and screening measurements, the protocol sweeps, `make_tables.py`,
every `fig*.py`, and finally `verify_paper_numbers.py`, which performs 116
checks against the values printed in the manuscript and exits non-zero if any of
them fails. One of them, the post-quantum signing ratio of Section 3.7.1, is
checked as an order of magnitude rather than a value, since signing time is not
stable enough to check against one: two runs on the same Apple M3 Max returned
107 and 165, and a Linux container returned 522. Table 9 reports the timing rows
as bands for the same reason, and `make_tables.py` writes them that way, so its
output matches the table on any machine whose times fall in the same bands. A run that ends with ALL CHECKS PASSED has reproduced the paper.

Individual stages can be run by hand in the same order; `generator.py` must be
first, since everything else consumes `scenarios.csv`.

The pipeline is deterministic given the seeds declared in Supplementary S3. On a
single core the original sequence completes in about a minute; the measurements
added in this revision are slower, dominated by the saturation sweep
(`run_misrouting_saturation.py`, roughly ten minutes) and the joint parameter
sweep (`operating_map.py`, roughly three minutes).

## Scope

The scenarios are synthetic. What the package establishes is internal: that the
manuscript reports what its code computed. Whether the generator's partial traces
resemble those of a deployment is the input-realism question stated in Section 4,
and Section 2.3 gives the predicate under which it can be measured on recorded
traces without access to verified outcomes.
